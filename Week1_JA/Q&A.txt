Q1. How do you decide whether a variable should be declared using let or const in JavaScript?

In JavaScript, var, let, and const are all used to declare variables, but they differ in scope, reassignment,and hoisting.

var is function-scoped, can be reassigned and redeclared, and may lead to unexpected issues because of hoisting.
let is block-scoped, can be reassigned but cannot be redeclared in the same scope, making it safer than var.
const is also block-scoped, but it cannot be reassigned after declaration, so it is mainly used for values that should 
remain constant.

After ES6, use const by default for better code safety and readability,let only when the variable value needs to change 
during execution.


a) console.log(x)
   var x = 10

o/p-> undefined

Hoisting is JavaScript’s default behavior where variable declarations are moved to the top of the scope during execution.
Because var x is hoisted but the value assignment happens later

b) console.log(y)
   const/let y = 20

o/p-> ReferenceError
This happens due to TDZ (Temporal Dead Zone) — the time between variable declaration and initialization.


| Feature   | var      | let       | const     |
| --------- | -------- | --------- | --------- |
| Redeclare | Yes      | No        | No        |
| Reassign  | Yes      | Yes       | No        |
| Scope     | Function | Block     | Block     |
| Hoisting  | Yes      | Yes (TDZ) | Yes (TDZ) |

Q2. What is the difference between == and === in JavScript ?

Loose Equality (==)
Compares only values and performs type coercion(converting one data type to another).

EX: 

console.log(5 == "5") // type coercion (string is getting converted to number 5 hence true)=> true
console.log(10=="10"); //type coercion (string is getting converted to number 10 hence true)=> true 
console.log(1==true); // Loose equality : type coercion (boolean is geting converted to truthy 1 )=> true 
console.log(null==undefined); //loose equality (==) treats both as equivalent empty values by a special coercion rule=>true

//condition true and hence prints Hello
if(true==1){

console.log("Hello");

}


Strict Equality (===)
Compares both value and datatype.

Ex:
console.log(5 === "5") // false
console.log(10==="10"); // false
console.log(1===true); // false
console.log(null===undefined); // false

//condition false and hence doesnot execute the loop
if(true===1){

console.log("Hello");

}

Q4. what is the difference between replace() and replaceAll()? When would you use replaceAll() in test Automation?

replace() changes only the first match.
replaceAll() changes every match in the string.
In test automation, we use it when the same word/character appears many times (like commas in prices or placeholders in 
locators).

// Number

let price = "1,20,000";
let cleanPrice = price.replaceAll(",", "");
console.log(cleanPrice); // 120000

//String

let text = "Test Automation is Fun";
let newText = text.replaceAll(" ", "-");
console.log(newText);//Test-Automation-is-Fun

//Alphanumeric

let code = "ORD-123-123-123";
let cleaned = code.replaceAll("-", "");
console.log(cleaned); // ORD123123123

//Alphanumeric with Special Symbols

let product = "PR@#123$%45!";
let cleaned = product.replaceAll(/[^a-zA-Z0-9]/g, "");
console.log(cleaned); // PR12345


let product = "PR@#123$%45!";

// Extract only alphabets
let letters = product.replace(/[^a-zA-Z]/g, "");

// Extract only digits
let numbers = product.replace(/[^0-9]/g, "");

// Extract only special characters
let specials = product.replace(/[a-zA-Z0-9]/g, "");

console.log("Letters:", letters);     // PR
console.log("Numbers:", numbers);     // 12345
console.log("Specials:", specials);   // @#$%!


replaceAll() in Test Automation
-------------------------------

Use Case: Essential for Data Sanitization.
Automation scripts often scrape prices or IDs that contain symbols ($, ,). Use replaceAll() with a regex to clean the data 
for mathematical comparisons.

const expectedPrice = "$1,000.50";
// Removes everything except numbers and the decimal point
const cleanPrice = expectedPrice.replaceAll(/[^0-9.]/g, ""); 
console.log(cleanPrice); // "1000.50"

Q5.  In JavaScript, why strings are immutable? What does it mean when we say 'modifying' a string?

Immutability means the data inside a string cannot be changed once created.
The Reality: When you "modify" a string, JavaScript creates a new string in a new memory location.
The Reference: The variable name simply stops pointing to the old memory address and starts pointing to the new one.

let str = "test"; // Points to memory location A
str = str + "leaf"; // Creates "testleaf" in location B; str now points to B

Q6. In an dynamic string: 'Order ID: #12345-Confirmed'. Write a quick logic using String methods (slice, split, or substring)
to extract just the ID 12345?

using split and slice
----------------------

Use split() to break the string at specific delimiters.

let productDetails = "Order ID: #12345-Confirmed";
let prod_status = productDetails.split("#"); // ["Order ID: ", "12345-Confirmed"]
let prod_id = prod_status[1].split('-');    // ["12345", "Confirmed"]

console.log(prod_id[0]); // Output: 12345

using Substring
---------------

let productDetails = "Order ID: #12345-Confirmed";

let start = productDetails.indexOf("#") + 1; // position after #
let end = productDetails.indexOf("-");       // position of -

let prod_id = productDetails.substring(start, end);

console.log(prod_id); // Output: 12345


| Feature                  | `slice`                         | `substring`                |
| ------------------------ | ------------------------------- | -------------------------- |
| Negative indices         | Allowed (count from end)        | Not allowed (treated as 0) |
| Swap start & end         | No                              | Yes, automatically swapped |
| Behavior on out-of-range | Returns empty string if invalid | Adjusts to valid range     |

Q7. We have a JavaScript function isValid(data) that checks if a field is populated.
if (data) { return true; }
This is causing a bug where the number 0 is treated as invalid (empty), but 0 is a valid input for our quantity field. 
How do you fix this validation logic?"

Handling "Falsy" Values (The 0 Bug)
Scenario: if (data) treats 0 as false, failing validation for quantity fields.

Solution: Check specifically for null and undefined using strict inequality.

function isValid(data) {
    // Explicitly allow 0 by only blocking null or undefined
    return data !== null && data !== undefined && data !== ""
}
console.log(isValid(0)); // Returns: true

Q10. "You have a continuous string of server logs:

ERROR: 404 [Time: 12:00] | INFO: Login Success [Time: 12:01] | ERROR: 500 [Time: 12:05]
Question: I need an array containing only the timestamps where an ERROR occurred. How would you approach this?

Task: Get an array of timestamps only where an ERROR occurred.

Solution: Combine split() with match() and Regular Expressions.

const logs = "ERROR: 404 [Time: 12:00] | INFO: Login Success [Time: 12:01] | ERROR: 500 [Time: 12:05]";
const entries = logs.split("|");

for (const entry of entries) {
    if (entry.includes("ERROR")) {
        const time = entry.match(/\[Time: (.*?)\]/);
        console.log(time[1]); // Output: 12:00, 12:05
    }
}

explanation:
------------
1) upon split:

[
 "ERROR: 404 [Time: 12:00] ",
 " INFO: Login Success [Time: 12:01] ",
 " ERROR: 500 [Time: 12:05]"
]

2) use for_of to loop through the log one by one.
3) check whether log contains the (ERROR)
4) Uses Regular Expression to extract the timestamp
/\[Time: → matches [Time:
(.*?) → captures the time value
\]/ → matches closing ]
5) time[1] contains only the captured timestamp value

function countVowels(str) {
  let vowels = "aeiouAEIOU";
  let count = 0;

  for (let char of str) {
    if (vowels.includes(char)) {
      count++;
    }

}
